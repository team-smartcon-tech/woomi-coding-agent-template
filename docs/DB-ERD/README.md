# DB-ERD

> 작성 2026-10-23 / 상태: 표준 (프로젝트가 테이블을 만들면 이 폴더의 그림을 채운다)

프로젝트 DB 의 테이블 관계도(ERD)를 두는 폴더다. 그림은 [Mermaid](https://mermaid.js.org/syntax/entityRelationshipDiagram.html) 텍스트라서 GitHub·VS Code(Mermaid 확장)에서 그대로 렌더링되고, 고칠 때는 텍스트만 바꾸면 된다.

> 이 규칙은 파생 프로젝트 Smart Planner 에서 2026-09-29 부터 쓰던 것을 일반화해 들여왔다(2.30-draft). 거기서는 스키마 파일만 읽다가 FK 타입 불일치(`text` ↔ `uuid`)와 엉뚱한 부모에 붙이는 실수가 나왔고, 사람이 그린 그림은 갱신을 빠뜨려도 아무것도 실패하지 않아 원격 FK 와 대조했을 때 선 모양이 틀린 관계가 둘 나왔다.

## 파일

| 파일 | 내용 | 상태 |
| --- | --- | --- |
| [현재-DB-ERD.md](현재-DB-ERD.md) | DB 에 **적용된** 테이블의 관계도와 테이블 ↔ 마이그레이션 표 | 비어 있음 — 첫 테이블을 만들 때 채운다 |

아직 적용 전인 테이블은 도메인별 **계획 문서**(`<도메인>-ERD.md`)에 따로 그린다. 계획 문서를 만들면 위 표에 행을 더한다.

## 무엇이 원천인가

ERD 는 **정리본**이다. 어긋나면 아래가 이긴다.

| 순위 | 원천 | 비고 |
| --- | --- | --- |
| 1 | `supabase/migrations/*.sql` | 실제로 적용되는 SQL. 컬럼·제약의 최종 기준 |
| 2 | [`.agents/data/DB_SCHEMA.md`](../../.agents/data/DB_SCHEMA.md) 5장 | 적용 상태·테이블별 설명 |
| 3 | [`.agents/data/DOMAIN_MODEL.md`](../../.agents/data/DOMAIN_MODEL.md) | 식별·삭제·값의 의미 같은 업무 계약 |

그림은 마이그레이션 SQL 을 읽어 그린다. 대조는 둘로 나뉜다.

- **실선 관계 ↔ FK — PR 마다 자동** ([`scripts/erd-check.mjs`](../../scripts/erd-check.mjs), [`db-checks`](../../.github/workflows/db-checks.yml) 워크플로). `supabase/migrations/` 에 SQL 이 생기면 켜진다. 격리 DB 에 마이그레이션을 전부 적용한 뒤, 「현재 ERD + 아직 적용 전인 계획 문서」 의 실선 관계와 FK 목록이 (부모, 자식, nullable) 단위로 개수까지 같은지 본다. 새 FK 를 만들고 그림을 안 고쳤거나, FK 가 있는데 점선으로(없는데 실선으로) 그렸으면 실패한다.
- **원격 적용 상태 — 사람이 본다.** CI 에 원격 접속 정보를 두지 않으므로 "현재 ERD 에 그린 테이블이 원격에 정말 있는가" 는 `supabase migration list` 또는 Supabase MCP(read-only) `list_tables` 로 따로 확인한다. 삭제 동작·엔티티 블록의 컬럼도 자동 대조 밖이다.

## 갱신하는 방법

마이그레이션을 추가하거나 적용 상태가 바뀔 때, **같은 PR 에서** 아래를 한다.

1. **새 테이블** — 아직 적용 전이면 계획 문서(`<도메인>-ERD.md`)에 먼저 그린다. 머리말에 `상태: 계획 — 미적용` 을 적는다. 격리 DB 는 미적용 마이그레이션까지 적용하므로, 현재 ERD 에도 계획 문서에도 없으면 "FK 가 있는데 실선이 없다" 로 실패한다.
2. **컬럼 추가·변경** — 관계와 식별에 쓰이는 컬럼(PK·FK·UK, 상태값)만 그림에 반영한다. 일반 컬럼은 그림에 넣지 않는다.
3. **계획 → 적용** — 적용을 확인하면 계획 문서의 관계와 엔티티를 [현재-DB-ERD.md](현재-DB-ERD.md) 로 옮기고, 계획 문서 머리말 `상태:` 를 `적용됨(현재-DB-ERD.md 로 이동)` 으로 고친다. **안 고치면 같은 관계가 두 번 세어져 실패한다.** 「테이블 ↔ 마이그레이션」 표에 적용일을 적는다.
4. 머리말의 `최종 수정` 날짜를 갱신하고, 위 「파일」 표의 상태를 맞춘다.
5. `.agents/data/DB_SCHEMA.md` 5장의 테이블 수와 이 폴더의 숫자가 다르면 `DB_SCHEMA.md` 를 따르고 여기를 고친다.

`erd-check` 가 읽는 머리말 규칙: `현재-DB-ERD.md` 는 항상 대조한다. 다른 문서는 `상태:` 줄에 `계획`·`미적용` 이 있으면 대조하고, `적용 완료`·`적용됨` 이 있으면 뺀다.

## DB 를 바꾸기 전에 ERD 로 검토한다 (필수)

테이블·컬럼·제약·뷰를 만들거나 바꾸기 전에 [현재-DB-ERD.md](현재-DB-ERD.md) 를 열어 아래를 확인하고, 결과를 마이그레이션 헤더나 PR 본문에 한 줄씩 남긴다. 문제가 없어도 "확인했고 문제 없음" 을 적는다. `AGENTS.md` 2장 Task Routing·`.agents/data/MIGRATION.md` 5장·`db-migration` 스킬이 이 절을 가리킨다 — **체크리스트 본문은 여기에만 둔다.**

| 확인 | 무엇을 보나 |
| --- | --- |
| 참조 대상 | FK 가 가리키는 테이블·컬럼이 ERD 에 있고 **타입이 같은가**. 테이블마다 PK 타입(`text`·`uuid`·`bigint`)이 다를 수 있다 |
| 삭제 동작 | 부모가 지워질 때 무엇이 함께 지워지나(`cascade`·`restrict`·`set null`). 최상위 부모가 `cascade` 로 묶여 있으면 하드 삭제 한 번에 딸린 행이 모두 사라진다. **행은 지워져도 Storage 객체는 남는다** |
| 붙일 부모 | 이 테이블이 어느 부모에 붙는가. 같은 이름의 개념이 다른 부모 아래 있을 수 있다 |
| nullable FK | null 이 무슨 뜻인지 정했는가(예: 프로젝트 FK 가 null = 전사 공통). 뜻이 없으면 `not null` |
| 식별과 중복 | 같은 행이 두 번 들어가면 안 되는가. 대리 키(`id`)만 있으면 중복이 막히지 않는다 → 자연 키 UNIQUE 를 걸거나 「중복 허용이 정상」 을 `DOMAIN_MODEL.md` 에 적는다 |
| 작성자 컬럼 | `created_by`·`updated_by` 류에 FK 를 걸지 말지 프로젝트에서 한 번 정해 `DOMAIN_MODEL.md` 에 적고 따른다(회원 삭제 시 이력이 함께 지워지거나 삭제가 막힌다) |
| 컬럼 삭제·이름 변경 | 그 컬럼을 참조하는 FK·뷰·제약·**코드의 명시 select** 가 있는가. 배포 순서를 정한다 — 새 컬럼을 쓰는 코드는 DB 적용 뒤에, 컬럼을 지우는 DB 변경은 코드가 참조를 끊은 뒤에. 어긋나면 `42703 undefined_column` 으로 쓰기가 실패한다 |
| 다른 문서 | 적용 전 계획 문서나 초안 SQL 이 이 테이블을 참조하는가. 참조 타입이 어긋나면 함께 고친다 |
| RLS | `enable row level security` + 불필요한 `anon`·`authenticated` 권한 회수를 했는가 — [`DB_SCHEMA.md`](../../.agents/data/DB_SCHEMA.md) 3.5 |
| 문서 | ERD·`DB_SCHEMA.md`·`DOMAIN_MODEL.md` 를 같은 PR 에서 갱신했는가 |

### 표기 약속

- 관계선: `||` 정확히 1, `|o` 0 또는 1, `o{` 0개 이상. 예) `projects |o--o{ events` = 이벤트는 프로젝트가 없어도 되고, 프로젝트 하나는 이벤트를 여럿 가진다.
- **실선(`--`) = DB 에 FK 가 있다.** **점선(`..`) = FK 는 없고 코드로만 연결된다.** 점선 관계에는 관계 이름에 이유를 적는다. 뷰와의 관계는 FK 가 없으므로 점선이다.
- 부모 쪽 표기는 FK 컬럼의 nullable 과 맞춘다 — `||` 는 `not null`, `|o` 는 nullable. 자동 대조가 이것까지 본다.
- 컬럼 뒤 따옴표 주석에는 FK 동작(`cascade`·`restrict`·`set null`), nullable 의미, 허용 값처럼 그림만 봐서는 알 수 없는 것을 적는다.
- 컬럼 타입은 `text`·`int`·`numeric`·`date`·`bool`·`jsonb`·`uuid`·`bigint`·`timestamptz` 만 쓴다(Mermaid 는 타입에 공백·괄호를 허용하지 않는다).
