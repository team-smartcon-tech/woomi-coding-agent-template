이 저장소를 처음 여는 사람을 **첫 커밋 1개까지** 데려가줘.

상대는 **코딩 에이전트를 처음 쓰는 비개발자**라고 전제한다. 브랜치·커밋·PR이 무엇인지 모른다고 보고, 용어가 필요하면 그 자리에서 한 줄로 풀어준다. 문서를 읽으라고 넘기지 말고 **네가 직접 실행하고 결과를 보여준다.** 사용자는 질문에 답만 하면 되게 한다.

먼저 지금부터 무엇을 할지 3~4줄로 알려주고 시작한다. 전체 10~15분이면 끝난다는 것도 말해준다.

## 1. 환경을 대신 잡아준다

사용자에게 명령을 시키지 말고 네가 실행한다. 각 단계는 결과만 한 줄로 알린다.

1. `git rev-parse --git-dir` — 실패하면 Git 저장소가 아직 없는 것이다. `git init`을 실행한다. ("작업 기록을 남길 준비를 했습니다" 정도로 설명한다.)
2. `git config core.hooksPath` — 값이 `.githooks`가 아니면 `git config core.hooksPath .githooks`를 실행한다. 안전장치가 켜진다.
3. `node scripts/agent-guard.cjs --selftest` — `agent-guard selftest OK`가 나오면 정상이다. 안 나오면 그 사실을 알리고, 안전장치 없이 계속할지 묻는다.

## 2. 빨간 글씨를 미리 설명한다

실습 중에 차단 메시지가 뜰 가능성이 높다. **뜨기 전에** 알려줘야 사용자가 겁먹지 않는다. 이렇게 전한다.

> 앞으로 `BLOCK:` 이나 `ERROR:` 로 시작하는 빨간 글씨가 뜰 수 있습니다. **고장이 아니라 안전장치가 작동한 것입니다.** 위험한 동작만 골라서 막습니다 — 비밀번호·인증서 파일 저장, `main`에 바로 올리기, 안전장치를 끄고 커밋하기, 작업 되돌리기, 데이터베이스 초기화. 뜨면 저에게 알려주세요. 왜 막혔는지 설명하고 안전한 방법으로 돌아가겠습니다.

## 3. 프로젝트가 무엇인지 묻는다

`AGENTS.md`의 `0. Project Overview` 빈칸 9개를 채운다. **아는 것만 답하면 되고 모르는 항목은 비워둬도 된다**고 먼저 알린다.

한 번에 하나씩 묻는다. 항목 이름만 던지지 말고 비개발자가 답할 수 있는 말로 바꿔서 묻는다.

| 항목 | 이렇게 묻는다 |
|---|---|
| Project name | 이 프로젝트를 뭐라고 부르나요 |
| What it does | 한 문장으로 무엇을 하는 물건인가요 |
| Main users | 누가 씁니까 |
| Core workflows | 그 사람들이 여기서 하는 일 2~3개는 무엇인가요 |
| Important data | 어떤 정보를 다루나요 (개인정보·결제 정보가 있으면 꼭 알려주세요) |
| Admin roles | 관리자 종류가 나뉘나요 |
| External services | 연결해야 할 외부 서비스가 있나요 (없으면 없다고) |
| Launch target | 언제까지 열어야 하나요 |
| Do not touch | 절대 건드리면 안 되는 것이 있나요 |

답을 받으면 `AGENTS.md` 0장의 빈칸을 채운다. 다 채운 뒤 사용자에게 그 부분을 보여주고, **이 내용이 앞으로 모든 작업의 기준이 된다**는 것을 알려준다.

## 4. 작업용 갈래를 만든다

`git switch -c feature/first-change` 를 실행한다.

왜 하는지 한 줄로 설명한다 — "`main`은 완성본을 두는 자리라 바로 고치지 않습니다. 갈래를 하나 만들어 거기서 작업하고, 나중에 확인한 뒤 합칩니다. 안전장치도 `main`에 바로 올리는 것을 막습니다."

## 5. 화면을 한 곳 바꾼다

`apps/web/app/routes/_app.tsx` 의 `Woomi Admin` 을 3단계에서 받은 Project name으로 바꾼다. 왼쪽 메뉴 맨 위 이름이라 **모든 화면에 보인다.**

- `apps/web/` 이 없는 프로젝트(문서만 복사해 얹은 경우)라면 이 단계는 건너뛴다. 대신 3단계의 `AGENTS.md` 변경만으로 6단계 없이 7단계 커밋으로 간다.
- `apps/web/app/routes/dashboard.tsx` 의 숫자는 **건드리지 않는다.** 같은 값이 두 곳에 있어서 위쪽을 고치면 화면이 안 바뀐다. 첫 실습에 쓰면 안 된다.

## 6. 눈으로 확인시킨다

`pnpm install` 후 `pnpm dev` 를 실행하고 `http://localhost:5173` 을 열라고 안내한다. 왼쪽 위 이름이 바뀐 것을 직접 보게 한다. 로그인이 필요하면 데모 계정 `admin@woomi.dev` / `admin1234` 를 알려준다.

확인이 끝나면 개발 서버를 멈추게 한다(`Ctrl+C`).

## 7. 커밋한다 — 여기가 끝이다

`git add` 후 `git commit` 한다. 메시지는 Conventional Commits 형식으로 쓰고, **그 형식이 무엇인지 한 줄로 설명**한다("`feat:`는 새 기능, `docs:`는 문서, `fix:`는 버그 수정입니다").

커밋 후 `git log --oneline -1` 로 결과를 보여주며 이렇게 마무리한다 — **"방금 첫 작업 기록이 남았습니다. 이 시점으로 언제든 돌아올 수 있습니다."**

## 8. 다음 단계만 알려준다 (여기서 실행하지 않는다)

지금까지 한 것은 전부 **이 컴퓨터 안에만** 있다. GitHub에 올려 팀과 나누려면 저장소가 따로 필요하다는 사실을 알린다.

`gh auth status` 로 GitHub CLI 상태를 확인한다.

- 인증돼 있으면: `gh repo create` 로 저장소를 만들고 올릴 수 있다고 **제안만** 한다. 하겠다고 하면 진행하되, **실행 전에 "이제 GitHub에 올립니다. 한번 올라가면 되돌리기 어렵습니다"를 반드시 먼저 말한다.**
- 없거나 인증이 안 돼 있으면: GitHub 계정을 만들고 웹에서 새 저장소를 만드는 절차를 3~4줄로 안내한다. 여기서 끝내도 된다고 분명히 말한다.

저장소를 만들었다면 `README.md`의 GitHub 저장소 보호 설정(Settings → Branches → ruleset)도 안내한다. 그것이 세 도구 모두에 걸리는 유일한 우회 불가 장치다.
